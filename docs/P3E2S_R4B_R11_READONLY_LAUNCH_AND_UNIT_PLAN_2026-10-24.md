# WPAuto P3-E2S-R4B-R11：只读启动适配与单次 unit 门禁计划

## 一、目标与依据

先解决当前可复现的本地测试启动阻断，再取得一次有完整诊断的 unit 结果。
本计划尚未执行，不将 R10-R1 的报告器合成通过扩大成实际启动通过。

已确认：固定镜像中 pnpm11.19.0 的版本读取正常，但 `pnpm exec node/tsx`
在只读环境退出1并出现 EROFS；单个合成测试也未生成报告。报告链路核心已修复，
实际 pnpm 正向启动仍失败。历史 R10 的精确首个失败原因继续 NOT_CONFIRMED。

采用最小策略：本地测试驱动直接使用固定 Node24.22.1 加载镜像内已安装、锁定的
tsx4.23.13，不经可能自动安装的包管理器启动。不升级、不下载、不开放写权限，
不更改 `.npmrc`、workspace 配置或依赖安全策略。

依据[tsx 官方 Node CLI 示例](https://github.com/privatenumber/tsx/blob/master/docs/dev-api/node-cli.md)：

```text
node --import=tsx --test --test-concurrency=1
  --test-reporter=<受审 reporter 的 file URL>
  --test-reporter-destination=<本轮私有结果文件>
  <本轮冻结的测试文件清单>
```

实际参数通过无 shell 的 argv 传递；上方仅为展示，不作为未审阅的直接执行命令。
官方示例不替代固定版本在当前只读镜像中的实测。

## 二、启动适配及合成门禁

1. 核对 R1 提交、干净工作区、固定 Test 镜像 ID及原编译指纹；应用、迁移、锁文件
   和 Node版本必须未漂移。只读取已安装 tsx 的版本、入口及哈希，不自动安装缺项。
2. 仅修改 unit/数据库测试的本地启动适配，使用该容器内 `process.execPath`，不使用
   Windows 编排 Node26作为应用运行时。保持报告模式、期限、输出预算和接受条件。
3. 在无网络、UID1000、只读根目录的同一镜像中运行一个合成 TypeScript 测试，验证
   实际 Node→tsx→test runner→独立报告文件→安全投影全链路。
4. 验证通过/断言失败/模块缺失/非法 reporter/非零退出/超时；任何失败保留固定诊断。
   不为验证助手而加载应用 main、连接数据库或调用真实 OAuth/MCP。
5. 保留已失败的 pnpm 探针及 R1 历史。若它不再是选定启动契约，应明确归为历史/可选
   诊断，另设必需的 Node+tsx 正向门禁；不能删除失败断言后冒称 pnpm 已修复。
6. 据实际测试设计冻结文件及必需用例清单；当前 unit 文件数为54。不得通过允许跳过
   必需正向门禁来制造通过。未知测试、异常缺失和不允许的 skip 一律失败。

合成门禁失败即停止。不得临时改为可写容器、root、联网安装、放宽验证或自动重试。

## 三、一次独立 unit 验收

只有上述启动门禁通过才执行一次，不调用完整数据库/A/B编排器：

- 复用固定 Test 镜像及其编译产物，不重复构建三种角色镜像。
- 必要的本地工具修复以逐文件白名单、只读挂载加载，记录每个文件哈希和来源；
  明确这是诊断覆盖层验收，不冒称镜像已经包含新工具或具备发布资格。
- 容器无外网/端口、无生产变量、凭据、SSH/Docker socket及用户配置挂载。
- 延续既有磁盘保护，不降低资源阈值。配置、清单和权限无法确认即停止。
- 仅运行冻结的 unit 清单一次，沿用240秒期限及受审输出/报告大小预算。
- 独立记录进程退出、报告状态、未映射事件数量、失败文件/行号/固定代码和必需用例
  完成情况；不记录原始日志、断言值、Token或异常正文。
- 首个失败后不修复并重跑；保存本轮有效诊断并停止。退出0、报告存在或清理成功
  都不能覆盖失败/缺失/不确定结果。核对清单前置检查失败也应有固定阶段结果。

结束后停止并确认本轮容器退出，保留必要脱敏结果。不清理其他 Docker 对象或用户文件。

## 四、通过条件与停止点

全部满足才报告 R11 unit 门禁通过：

1. 固定 Node/tsx 的只读合成启动成功，无安装、下载或权限放宽。
2. 进程正常结束，报告版本、run ID、phase及清单匹配。
3. 所有必需 unit 用例执行通过，无未知事件、遗漏或未批准跳过。
4. 前后源码、镜像、配置和保护边界未变；本轮容器已停止。
